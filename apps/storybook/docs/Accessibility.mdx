# Accessibility

Native-UI targets **WCAG 2.2 Level AA** on both iOS and Android. Every
interactive component ships with semantic roles, labelled states, a
44 × 44 pt minimum hit target, and respects the user's OS-level
preferences (Reduce Motion, Dynamic Type, Bold Text, High Contrast,
Reduce Transparency).

> **Principle.** Accessibility is not a list of things you remember to
> do when you use the library - it is a set of defaults that ship with
> every component and that your code cannot accidentally opt out of.

---

## 1. What you get for free

### 1.1 Semantic roles

Every interactive primitive sets the correct `accessibilityRole`:

| Component | Role | Notes |
|---|---|---|
| `Button` | `button` | `busy` while `loading`, `disabled` when disabled |
| `IconButton` | `button` | `accessibilityLabel` is **required** (compile error without it) |
| `Checkbox` | `checkbox` | Exposes `checked` as `true`, `false` or `'mixed'` |
| `Radio` | `radio` | Nested in `radiogroup` container for arrow-key nav |
| `Switch` | `switch` | Native role via React Native `<Switch>` |
| `Input` / `TextArea` | inherited | Error messages use `accessibilityLiveRegion="polite"` |
| `SearchBar` | `search` | Announces result count changes when wired to results |
| `ProgressBar` | `progressbar` | `accessibilityValue.now/min/max` auto-filled |
| `Modal` / `BottomSheet` | modal dialog | Focus trapped on open, restored on close |
| `Heading` | `header` | Screen readers announce heading level |
| `ListItem` | `button` (pressable) / `text` | Role matches whether `onPress` is provided |
| `Toast` | `alert` | Announced by screen readers on enter |

### 1.2 State announcements

Interactive components expose complete `accessibilityState` objects:

- `disabled` - announced as "dimmed" / "disabled".
- `checked` - tri-state for `Checkbox` indeterminate.
- `selected` - for `Radio` and selected `Chip`.
- `busy` - for `Button` during `loading`, for `SearchBar` while
  debouncing.
- `expanded` - for `BottomSheet` and collapsible `Section`.

### 1.3 Live regions

Validation errors (`Input`, `TextArea`, `Select`) use
`accessibilityLiveRegion="polite"`. When the error message flips from
empty to populated, the screen reader announces it without interrupting
the current focus context.

Toasts use `alert` role (`aria-live="assertive"` on web) so critical
messages are announced immediately.

## 2. Touch targets

Every pressable meets platform minimums:

| Platform | Minimum | How the library enforces it |
|---|---|---|
| iOS | 44 × 44 pt (HIG) | `hitSlop.ios = { top: 8, bottom: 8, left: 8, right: 8 }` around any smaller visual |
| Android | 48 × 48 dp (Material) | `hitSlop.android = { top: 10, bottom: 10, left: 10, right: 10 }` |

```tsx
// Built-in token (exported for custom components)
import { hitSlop } from '@polprog/native-ui';

<Pressable hitSlop={hitSlop.ios} /* or platform-select */>
```

> **Do not** override `hitSlop` to shrink targets. If a visual is
> smaller than 44 pt, keep the default slop - the extra invisible area
> is what makes the button tappable for users with tremors or oily /
> gloved fingers.

## 3. Color contrast (WCAG 2.2 AA)

- Every `textOn<Background>` token is picked by `getContrastText()` to
  guarantee a contrast ratio of **≥ 4.5 : 1** for body copy and
  **≥ 3 : 1** for large text (≥ 18 pt / 14 pt bold).
- Semantic `success` / `warning` / `error` colors are tuned against
  surface tokens, not just white - so errors on dark mode are still
  legible.
- `highContrast: true` strengthens `textSecondary` and `textTertiary`
  toward `textPrimary` for low-vision users without changing layout.

### Verifying contrast in stories

The **a11y** addon panel at the bottom of every story runs axe-core
live. Violations appear as red items you can click to expand. Every
story also runs as a Vitest browser test (`npm run test --workspace=@polprog/storybook`,
or the testing widget in the Storybook sidebar), and CI fails on any
violation in stories whose `parameters.a11y.test` is `'error'`, the
project default. Stories with known, tracked issues use `'todo'`, which
reports violations as warnings.

## 4. Motion and animation

The `reduceAnimations` config toggle (or the OS "Reduce Motion"
setting surfaced through it) flips the whole library into a
no-animation branch:

| Component | Default | `reduceAnimations: true` |
|---|---|---|
| `PressableScale` | Spring scale to 0.97 on press | No-op (instant) |
| `Skeleton` | Linear shimmer | Static base color |
| `Toast` | Slide + fade 300 ms | Instant appear / disappear |
| `BottomSheet` | Spring slide 250 ms | Instant open / close |
| `Modal` | Fade 200 ms | Instant |
| `ConfettiOverlay` | 60 fps particle burst | No-op (visual stays, no motion) |

```tsx
import { AccessibilityInfo } from 'react-native';
// real-world wiring:
const [reduce, setReduce] = useState(false);
useEffect(() => {
  AccessibilityInfo.isReduceMotionEnabled().then(setReduce);
  const sub = AccessibilityInfo.addEventListener('reduceMotionChanged', setReduce);
  return () => sub.remove();
}, []);

<NativeUIProvider config={{ reduceAnimations: reduce }}>
```

## 5. Font scaling (Dynamic Type)

Three library-level scale tiers that **compose on top of** the system
font scale from OS accessibility settings:

| Tier | Library adjustment | With OS "XL" text scale |
|---|---|---|
| `default` | ±0 px | still respects OS scale |
| `medium` | +2 px | +2 + OS |
| `large` | +4 px | +4 + OS |

Every type variant is defined via `fontSize` + `lineHeight` tokens that
scale together, so no paragraph ever clips vertically under Dynamic
Type.

> **Tip.** To mirror iOS "Large Text" exactly, use
> `PixelRatio.getFontScale()` and map > 1.2 -> `'large'`, > 1.0 ->
> `'medium'`, else `'default'`.

---

## 6. Icon-only buttons

`IconButton` **requires** `accessibilityLabel` at the TypeScript level:

```tsx
// ❌ compile error - no accessibilityLabel
<IconButton icon={<SearchIcon />} onPress={open} />

// ✅
<IconButton icon={<SearchIcon />} accessibilityLabel="Search" onPress={open} />
```

This is a deliberate library-level escape hatch elimination: you cannot
ship an unlabelled icon button even by accident.

---

## 7. Focus management

- `Modal` and `BottomSheet` trap focus inside on open and restore it to
  the opening trigger on close.
- `Input` exposes a `focus()` / `blur()` ref API so forms can drive
  focus explicitly.
- `BottomTabBar` sets `accessibilityRole="tablist"` with each tab as
  `tab` + `accessibilityState.selected` so VoiceOver announces "Tab 1
  of 4, selected".

---

## 8. RTL support

Native-UI uses `I18nManager.isRTL` where layout direction matters
(`HStack`, `PressableScale` pressed highlights, `HeaderBar` back
button). Stories expose **Locale** in the **Appearance** menu with an **AR** option that
flips the storybook canvas to `direction: 'rtl'` live.

---

## 9. Best practices for consuming apps

### Do ✅

- Provide `accessibilityLabel` to **every** icon-only button.
- Use semantic `Text` variants (`h1`, `h2`, `body`, `caption`) for
  proper heading hierarchy - screen readers parse them.
- Use `<Heading level={n}>` for section headings
  (`accessibilityRole="header"` + `aria-level={n}` on web).
- Run VoiceOver (iOS: triple-click side button) and TalkBack (Android:
  Settings > Accessibility > TalkBack) on every new screen **before**
  code review.
- Respect `reduceAnimations` in any custom animations you add.
- Test in **Larger Accessibility Sizes** on iOS to catch truncation.
- Pair color with icon or text when conveying state - colour is a cue,
  never the sole signal.

### Don't ❌

- Don't disable `accessibilityLabel` to save keystrokes.
- Don't rely on color alone (red = error) - always add an icon / word.
- Don't use `<Text variant="h2">` as a visual style while
  semantically a subtitle - use the right variant and adjust via
  `semantic` tokens if needed.
- Don't override `hitSlop` to shrink touch targets.
- Don't add custom animations that ignore `reduceAnimations`.
- Don't interrupt the user's task with `Toast` variant `error` when a
  validation error inside a form would do.

---

## 10. Pre-release a11y checklist

Run this before every release tag.

- [ ] **Axe** panel clean on every story (0 violations in `build-storybook`).
- [ ] **VoiceOver** sweep of each flagship screen - titles, buttons,
      form errors all announce correctly.
- [ ] **TalkBack** sweep - focus order matches visual order.
- [ ] Dynamic Type at **XL** on iOS - no clipped text, no overlap.
- [ ] **Reduce Motion** on iOS - no parallax, no bouncy transitions.
- [ ] **High Contrast** on iOS / **High Contrast Text** on Android - all
      semantic state colors still legible.
- [ ] **RTL** (`I18nManager.forceRTL(true)`) - `HeaderBar` back button
      flips, lists right-align.
- [ ] Color-blind sanity check (`protanopia` / `deuteranopia` / `tritanopia`) -
      no state conveyed by colour alone.

# Dostępność

Native-UI celuje w **WCAG 2.2 poziom AA** na iOS i Androidzie. Każdy
interaktywny komponent ma semantyczne role, opisane stany, minimalny obszar
dotyku 44 × 44 pt i respektuje preferencje użytkownika z poziomu systemu
(Reduce Motion, Dynamic Type, Bold Text, High Contrast, Reduce
Transparency).

> **Zasada.** Dostępność to nie lista rzeczy, o których trzeba pamiętać
> przy korzystaniu z biblioteki - to zestaw ustawień domyślnych, które
> każdy komponent ma od razu i których Twój kod nie może przypadkiem
> wyłączyć.

---

## 1. Co dostajesz od razu

### 1.1 Role semantyczne

Każdy interaktywny prymityw ustawia właściwe `accessibilityRole`:

| Komponent | Rola | Uwagi |
|---|---|---|
| `Button` | `button` | `busy` podczas `loading`, `disabled`, gdy jest wyłączony |
| `IconButton` | `button` | `accessibilityLabel` jest **wymagany** (bez niego błąd kompilacji) |
| `Checkbox` | `checkbox` | Udostępnia `checked` jako `true`, `false` lub `'mixed'` |
| `Radio` | `radio` | Zagnieżdżony w kontenerze `radiogroup` dla nawigacji strzałkami |
| `Switch` | `switch` | Natywna rola przez `<Switch>` z React Native |
| `Input` / `TextArea` | dziedziczona | Komunikaty błędów używają `accessibilityLiveRegion="polite"` |
| `SearchBar` | `search` | Ogłasza zmiany liczby wyników, gdy jest połączony z wynikami |
| `ProgressBar` | `progressbar` | `accessibilityValue.now/min/max` wypełniane automatycznie |
| `Modal` / `BottomSheet` | okno modalne | Fokus uwięziony po otwarciu, przywracany po zamknięciu |
| `Heading` | `header` | Czytniki ekranu ogłaszają poziom nagłówka |
| `ListItem` | `button` (klikalny) / `text` | Rola zależy od tego, czy podano `onPress` |
| `Toast` | `alert` | Ogłaszany przez czytniki ekranu po pojawieniu się |

### 1.2 Ogłaszanie stanów

Interaktywne komponenty udostępniają pełne obiekty `accessibilityState`:

- `disabled` - ogłaszany jako „dimmed” / „disabled”.
- `checked` - trójstanowy dla nieokreślonego stanu `Checkbox`.
- `selected` - dla `Radio` i zaznaczonego `Chip`.
- `busy` - dla `Button` podczas `loading`, dla `SearchBar` w trakcie
  debounce.
- `expanded` - dla `BottomSheet` i zwijanego `Section`.

### 1.3 Regiony live

Błędy walidacji (`Input`, `TextArea`, `Select`) używają
`accessibilityLiveRegion="polite"`. Gdy komunikat błędu zmienia się z
pustego na wypełniony, czytnik ekranu ogłasza go bez przerywania bieżącego
kontekstu fokusu.

Toasty używają roli `alert` (`aria-live="assertive"` w wersji web), więc
krytyczne komunikaty są ogłaszane natychmiast.

---

## 2. Obszary dotyku

Każdy klikalny element spełnia minimalne wymagania platformy:

| Platforma | Minimum | Jak egzekwuje to biblioteka |
|---|---|---|
| iOS | 44 × 44 pt (HIG) | `hitSlop.ios = { top: 8, bottom: 8, left: 8, right: 8 }` wokół każdego mniejszego elementu |
| Android | 48 × 48 dp (Material) | `hitSlop.android = { top: 10, bottom: 10, left: 10, right: 10 }` |

```tsx
// Wbudowany token (eksportowany na potrzeby własnych komponentów)
import { hitSlop } from '@polprog/native-ui';

<Pressable hitSlop={hitSlop.ios} /* lub wybór zależny od platformy */>
```

> **Nie** nadpisuj `hitSlop`, żeby zmniejszyć obszar dotyku. Jeśli element
> jest mniejszy niż 44 pt, zostaw domyślny slop - dodatkowy niewidoczny
> obszar sprawia, że przycisk da się trafić osobom z drżeniem rąk albo z
> wilgotnymi palcami lub w rękawiczkach.

## 3. Kontrast kolorów (WCAG 2.2 AA)

- Każdy token `textOn<Background>` jest dobierany przez `getContrastText()`
  tak, by zagwarantować współczynnik kontrastu **≥ 4.5 : 1** dla tekstu
  podstawowego i **≥ 3 : 1** dla dużego tekstu (≥ 18 pt / 14 pt pogrubiony).
- Semantyczne kolory `success` / `warning` / `error` są dostrajane względem
  tokenów powierzchni, a nie tylko bieli - dzięki temu błędy w trybie
  ciemnym pozostają czytelne.
- `highContrast: true` przybliża `textSecondary` i `textTertiary` do
  `textPrimary` z myślą o osobach słabowidzących, bez zmiany układu.

### Sprawdzanie kontrastu w story

Panel dodatku **a11y** na dole każdej story uruchamia axe-core na żywo.
Naruszenia pojawiają się jako czerwone pozycje, które można rozwinąć
kliknięciem. Każda story działa też jako test przeglądarkowy Vitest
(`npm run test --workspace=@polprog/storybook` lub widżet testów w pasku
bocznym Storybooka), a CI kończy się błędem przy każdym naruszeniu w
story, których `parameters.a11y.test` ma wartość `'error'`, czyli domyślną
dla projektu. Story ze znanymi, śledzonymi problemami używają `'todo'`,
które zgłasza naruszenia jako ostrzeżenia.

## 4. Ruch i animacje

Przełącznik konfiguracji `reduceAnimations` (albo udostępnione przez niego
systemowe ustawienie „Reduce Motion”) przełącza całą bibliotekę w tryb bez
animacji:

| Komponent | Domyślnie | `reduceAnimations: true` |
|---|---|---|
| `PressableScale` | Sprężynowe skalowanie do 0.97 przy naciśnięciu | Brak efektu (natychmiast) |
| `Skeleton` | Liniowy shimmer | Statyczny kolor bazowy |
| `Toast` | Wsunięcie + zanikanie 300 ms | Natychmiastowe pojawienie / zniknięcie |
| `BottomSheet` | Sprężynowe wsunięcie 250 ms | Natychmiastowe otwarcie / zamknięcie |
| `Modal` | Zanikanie 200 ms | Natychmiast |
| `ConfettiOverlay` | Wybuch cząsteczek w 60 fps | Brak efektu (element widoczny, bez ruchu) |

```tsx
import { AccessibilityInfo } from 'react-native';
// podłączenie w prawdziwej aplikacji:
const [reduce, setReduce] = useState(false);
useEffect(() => {
  AccessibilityInfo.isReduceMotionEnabled().then(setReduce);
  const sub = AccessibilityInfo.addEventListener('reduceMotionChanged', setReduce);
  return () => sub.remove();
}, []);

<NativeUIProvider config={{ reduceAnimations: reduce }}>
```

## 5. Skalowanie czcionek (Dynamic Type)

Trzy poziomy skali na poziomie biblioteki, które **nakładają się na**
systemową skalę czcionek z ustawień dostępności systemu:

| Poziom | Korekta biblioteki | Przy systemowej skali tekstu „XL” |
|---|---|---|
| `default` | ±0 px | nadal respektuje skalę systemu |
| `medium` | +2 px | +2 + system |
| `large` | +4 px | +4 + system |

Każdy wariant typografii jest zdefiniowany przez tokeny `fontSize` +
`lineHeight`, które skalują się razem, więc żaden akapit nie zostanie
przycięty w pionie przy Dynamic Type.

> **Wskazówka.** Aby dokładnie odwzorować iOS „Large Text”, użyj
> `PixelRatio.getFontScale()` i mapuj > 1.2 -> `'large'`, > 1.0 ->
> `'medium'`, w pozostałych przypadkach `'default'`.

---

## 6. Przyciski z samą ikoną

`IconButton` **wymaga** `accessibilityLabel` na poziomie TypeScriptu:

```tsx
// ❌ błąd kompilacji - brak accessibilityLabel
<IconButton icon={<SearchIcon />} onPress={open} />

// ✅
<IconButton icon={<SearchIcon />} accessibilityLabel="Search" onPress={open} />
```

To celowe usunięcie furtki na poziomie biblioteki: nie da się wydać
przycisku z ikoną bez etykiety, nawet przez przypadek.

---

## 7. Zarządzanie fokusem

- `Modal` i `BottomSheet` po otwarciu więżą fokus w swoim wnętrzu, a po
  zamknięciu przywracają go do elementu, który je otworzył.
- `Input` udostępnia przez ref API `focus()` / `blur()`, dzięki czemu
  formularze mogą jawnie sterować fokusem.
- `BottomTabBar` ustawia `accessibilityRole="tablist"`, a każdą kartę jako
  `tab` + `accessibilityState.selected`, więc VoiceOver ogłasza „Tab 1
  of 4, selected”.

---

## 8. Obsługa RTL

Native-UI korzysta z `I18nManager.isRTL` tam, gdzie kierunek układu ma
znaczenie (`HStack`, podświetlenia po naciśnięciu w `PressableScale`,
przycisk powrotu w `HeaderBar`). Story udostępniają **Locale** w menu
**Appearance** z opcją **AR**, która na żywo przełącza kanwę Storybooka
na `direction: 'rtl'`.

## 9. Dobre praktyki dla aplikacji korzystających z biblioteki

### Rób tak ✅

- Podawaj `accessibilityLabel` **każdemu** przyciskowi z samą ikoną.
- Używaj semantycznych wariantów `Text` (`h1`, `h2`, `body`, `caption`),
  żeby zachować poprawną hierarchię nagłówków - czytniki ekranu ją
  analizują.
- Używaj `<Heading level={n}>` do nagłówków sekcji
  (`accessibilityRole="header"` + `aria-level={n}` w wersji web).
- Uruchamiaj VoiceOver (iOS: trzykrotne naciśnięcie przycisku bocznego) i
  TalkBack (Android: Ustawienia > Ułatwienia dostępu > TalkBack) na każdym
  nowym ekranie **przed** code review.
- Respektuj `reduceAnimations` we wszystkich własnych animacjach.
- Testuj z **Larger Accessibility Sizes** na iOS, żeby wychwycić obcięty
  tekst.
- Przekazując stan, łącz kolor z ikoną lub tekstem - kolor jest
  wskazówką, nigdy jedynym sygnałem.

### Nie rób tak ❌

- Nie pomijaj `accessibilityLabel`, żeby zaoszczędzić kilka znaków.
- Nie polegaj wyłącznie na kolorze (czerwony = błąd) - zawsze dodaj ikonę
  lub słowo.
- Nie używaj `<Text variant="h2">` jako stylu wizualnego dla czegoś, co
  semantycznie jest podtytułem - użyj właściwego wariantu i w razie
  potrzeby dostosuj go tokenami `semantic`.
- Nie nadpisuj `hitSlop`, żeby zmniejszyć obszar dotyku.
- Nie dodawaj własnych animacji, które ignorują `reduceAnimations`.
- Nie przerywaj zadania użytkownika `Toast` w wariancie `error`, gdy
  wystarczyłby błąd walidacji wewnątrz formularza.
