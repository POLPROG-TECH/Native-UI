# App shell pattern

A production React Native app typically shares the same structural
skeleton: a full-screen container, a header bar, scrollable body, and
optionally a bottom tab rail. This page shows the one **canonical way**
to assemble those primitives so screens stay visually consistent across
your app.

Produkcyjna aplikacja React Native zwykle ma ten sam szkielet strukturalny:

## Kanoniczna kompozycja

</Translated>

```tsx
import { useSafeAreaInsets } from 'react-native-safe-area-context';
import {
  ScreenContainer,
  HeaderBar,
  BottomTabBar,
  Section,
  VStack,
} from '@polprog/native-ui';

export function HomeScreen() {
  const insets = useSafeAreaInsets();

  return (
    <ScreenContainer
      scroll
      header={<HeaderBar title="Home" />}
      footer={
        <BottomTabBar
          items={TABS}
          activeKey="home"
          safeBottomInset={insets.bottom}
          onSelect={navigate}
        />
      }
    >
      <VStack gap="lg" p="lg">
        <Section title="Today">…</Section>
        <Section title="Recent">…</Section>
      </VStack>
    </ScreenContainer>
  );
}
```

<Translated lang="en">

## Rules

1. **`ScreenContainer` owns safe-area top.** Never add `paddingTop: insets.top`
   manually - it is handled internally via `<SafeAreaView edges={['top']}>`.
2. **`BottomTabBar` owns safe-area bottom.** Pass `safeBottomInset` explicitly
   so the bar grows past the home indicator. `ScreenContainer` must NOT add
   bottom padding when a footer is present.
3. **Header and footer never scroll.** They are slotted outside the scroll
   view. Body scrolling is clamped between them.
4. **Use `Section` for grouped content.** Sections define their own padding
   and rhythm - do not nest `Card` inside `Section` unless explicitly needed.
5. **Screens are locale-agnostic.** Titles and actions pass through i18n
   at call site. The library components never hardcode copy.
6. **Use `VStack gap="lg"` as the body separator.** Not `<Divider>`, not
   `paddingBottom: 24` - a single `gap` keeps the cadence consistent.

## Platform parity

| Surface | iOS behaviour | Android behaviour |
|---|---|---|
| Status bar | translucent; `ScreenContainer` renders under it | translucent; material colour inherited |
| Header | 44 pt tall (regular) / 96 pt tall (large-title mode) | 56 dp tall |
| Bottom bar | 4 pt top + 4 pt bottom + safe inset (≈ 34 pt) | 4 pt top + 8 pt bottom + gesture inset (≈ 24 pt) |
| Keyboard | `KeyboardAvoidingView` behaviour=`padding` | behaviour=`height` |

## Anti-patterns

❌ Do **not** wrap `ScreenContainer` in an outer `SafeAreaView`. Double
safe-area insets create visible gutters above the header.

❌ Do **not** stack two `HeaderBar`s (e.g. "app bar" + "section bar"). Use
`Section title="…"` for sub-section titles; reserve `HeaderBar` for the
screen-level title.

❌ Do **not** put the bottom tab inside the scroll view. It must remain
statically pinned to the viewport bottom.

❌ Do **not** hardcode `paddingBottom: 90` to "make room for the tab bar".
Use the footer slot; `ScreenContainer` computes content inset automatically.

## Reference

See the **BottomTabBar**, **HeaderBar** and **ScreenContainer** stories
for interactive examples of each primitive used in this pattern.

## Zasady

1. **`ScreenContainer` odpowiada za górny safe area.** Nigdy nie dodawaj
   ręcznie `paddingTop: insets.top` - jest to obsługiwane wewnętrznie przez
   `<SafeAreaView edges={['top']}>`.
2. **`BottomTabBar` odpowiada za dolny safe area.** Przekaż jawnie
   `safeBottomInset`, żeby pasek sięgał poza wskaźnik ekranu głównego.
   `ScreenContainer` NIE może dodawać dolnego paddingu, gdy jest obecna
   stopka.
3. **Nagłówek i stopka nigdy się nie przewijają.** Są umieszczone w
   slotach poza widokiem przewijania. Przewijana treść jest ograniczona
   między nimi.
4. **Używaj `Section` do grupowania treści.** Sekcje definiują własny
   padding i rytm - nie zagnieżdżaj `Card` w `Section`, chyba że jest to
   wyraźnie potrzebne.
5. **Ekrany są niezależne od języka.** Tytuły i akcje przechodzą przez i18n
   w miejscu wywołania. Komponenty biblioteki nigdy nie mają tekstów
   wpisanych na sztywno.
6. **Używaj `VStack gap="lg"` jako separatora treści.** Nie `<Divider>`, nie
   `paddingBottom: 24` - jeden `gap` utrzymuje spójny rytm.

## Zgodność między platformami

| Powierzchnia | Zachowanie na iOS | Zachowanie na Androidzie |
|---|---|---|
| Pasek stanu | przezroczysty; `ScreenContainer` renderuje się pod nim | przezroczysty; dziedziczy kolor z Material |
| Nagłówek | 44 pt wysokości (zwykły) / 96 pt wysokości (tryb dużego tytułu) | 56 dp wysokości |
| Dolny pasek | 4 pt u góry + 4 pt u dołu + inset safe area (≈ 34 pt) | 4 pt u góry + 8 pt u dołu + inset gestów (≈ 24 pt) |
| Klawiatura | `KeyboardAvoidingView` behaviour=`padding` | behaviour=`height` |

## Antywzorce

❌ **Nie** opakowuj `ScreenContainer` w zewnętrzny `SafeAreaView`. Podwójne
insety safe area tworzą widoczne odstępy nad nagłówkiem.

❌ **Nie** układaj dwóch `HeaderBar` jeden na drugim (np. „app bar” +
„section bar”). Do tytułów podsekcji używaj `Section title="…"`;
`HeaderBar` zostaw na tytuł całego ekranu.

❌ **Nie** umieszczaj dolnego paska kart w widoku przewijania. Musi pozostać
statycznie przypięty do dołu ekranu.

❌ **Nie** wpisuj na sztywno `paddingBottom: 90`, żeby „zrobić miejsce na
pasek kart”. Użyj slotu stopki; `ScreenContainer` sam wylicza inset treści.
