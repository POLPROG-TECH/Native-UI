# Theming

Native-UI is driven by a **single resolved theme object** that every
component consumes via hooks. You never touch individual components to
rebrand - you change the provider config and the whole tree updates
synchronously.

The theme system is built around four concepts:

1. **Theme variants** - complete visual identities (**Aurora**, the original
   green, near-black look, and **Bloom**, a soft violet, rounded look) that
   bundle colours, radii, elevation, type density and default fonts. Switch with
   `config={{ theme: 'bloom' }}`, or use **Variant** in the **Appearance** menu above.
   The biggest Aurora-to-Bloom differences show on `Card`, `Button`, `Chip`,
   `Switch` and the `SettingsRow` list - open the **Patterns / Theme variants**
   story to see them side by side.
2. **Presets** - curated accent + neutral pairings (each variant ships its own).
3. **Custom accent** - a single hex color that rebrands the whole app.
4. **Semantic tokens** - designer-facing aliases that decouple intent
   from raw values (`semantic.colors.danger` rather than `colors.error`).

# Motywy

Native-UI opiera się na **jednym rozwiązanym obiekcie motywu**, z którego
każdy komponent korzysta przez hooki. Aby zmienić identyfikację wizualną,
nigdy nie ruszasz pojedynczych komponentów - zmieniasz konfigurację
providera, a całe drzewo aktualizuje się synchronicznie.

System motywów opiera się na czterech pojęciach:

1. **Warianty motywu** - kompletne identyfikacje wizualne (**Aurora**,
   oryginalny zielony, niemal czarny wygląd, oraz **Bloom**, miękki,
   fioletowy, zaokrąglony wygląd), które łączą kolory, promienie, elewację,
   gęstość typografii i domyślne fonty. Przełączysz je przez
   `config={{ theme: 'bloom' }}` albo opcją **Variant** w menu **Appearance** powyżej.
   Największe różnice między Aurorą a Bloom widać na `Card`, `Button`, `Chip`,
   `Switch` i liście `SettingsRow` - otwórz story **Patterns / Theme variants**,
   aby zobaczyć je obok siebie.
2. **Presety** - dobrane pary kolorów akcentu i neutralnych (każdy wariant ma własne).
3. **Własny akcent** - jeden kolor hex, który zmienia identyfikację całej aplikacji.
4. **Tokeny semantyczne** - aliasy dla projektantów, które oddzielają
   intencję od surowych wartości (`semantic.colors.danger` zamiast `colors.error`).

## 2. Color presets

Each preset ships matched light **and** dark palettes plus a primary
accent. Switching preset is a one-prop change.

| Preset | Light accent | Dark accent | Use case |
|---|---|---|---|
| `default` | Indigo `#4F46E5` | Indigo `#818CF8` | General-purpose enterprise apps |
| `midnight` | Slate blue `#6366F1` | Slate `#A5B4FC` | Professional / corporate |
| `ocean` | Cyan `#0891B2` | Cyan `#22D3EE` | Fresh, modern utilities |
| `forest` | Emerald `#059669` | Emerald `#34D399` | Health, nature, sustainability |
| `sunset` | Amber `#D97706` | Amber `#FBBF24` | Warm consumer / lifestyle |
| `rose` | Pink `#E11D48` | Pink `#FB7185` | Fitness, community, media |
| `amoled` | White `#FFFFFF` | Pure white on `#000000` | OLED battery savings |

## 3. Tryby kolorów

</Translated>

```tsx
<NativeUIProvider config={{ colorMode: 'system' }}>
```

<Translated lang="en">

- `'light'` / `'dark'` - forced, useful for settings screens that let
  users override the OS preference.
- `'system'` - follows `useColorScheme()`; re-renders automatically when
  the user flips the OS toggle.

Each preset resolves to a full `ColorScheme` of 25+ semantic tokens so
you never hand-pick a hex.

### What you get (resolved scheme)

<details>
<summary>Surfaces</summary>

- `background` - App root background.
- `surface` - Card / sheet / list background.
- `surfaceElevated` - Modals, popovers.
- `surfaceSecondary` - Grouped content (settings sections).
- `overlay` - Semi-transparent backdrop behind modals / sheets.

</details>

<details>
<summary>Text</summary>

- `textPrimary` - Body + headings.
- `textSecondary` - Captions, helper text.
- `textTertiary` - Muted / placeholder.
- `textInverse` - Text that sits on colored backgrounds.
- `textOnPrimary` - Text on the accent color (auto WCAG-picked).

</details>

<details>
<summary>Semantic state colors</summary>

- `primary` / `primaryLight` / `primaryDark`
- `success` / `successLight`
- `warning` / `warningLight`
- `error` / `errorLight`
- `info` / `infoLight`

Each `*Light` variant is pre-tinted for badges, callouts and tinted
surfaces (~9 % alpha over the base).

</details>

<details>
<summary>System</summary>

- `border` / `borderLight` - Hairlines at 1px / 0.5px.
- `divider` - List separators.
- `shadow` - Elevation colour (iOS shadow, Android elevation).

</details>

## 4. Custom accent (brand override)

One hex color. Done.

</Translated>

<Translated lang="pl">

- `'light'` / `'dark'` - wymuszone, przydatne na ekranach ustawień, które
  pozwalają użytkownikom nadpisać preferencję systemu.
- `'system'` - podąża za `useColorScheme()`; renderuje się ponownie

Każdy preset rozwiązuje się do pełnego `ColorScheme` z ponad 25 tokenami

<details>
<summary>Powierzchnie</summary>

- `surface` - Tło karty / arkusza / listy.
- `surfaceElevated` - Modale, popovery.
- `surfaceSecondary` - Pogrupowana treść (sekcje ustawień).
- `overlay` - Półprzezroczyste tło za modalami / arkuszami.

</details>

<details>
<summary>Tekst</summary>

- `textPrimary` - Treść + nagłówki.
- `textSecondary` - Podpisy, tekst pomocniczy.
- `textTertiary` - Wyciszony / placeholder.
- `textInverse` - Tekst na kolorowych tłach.
- `textOnPrimary` - Tekst na kolorze akcentu (dobierany automatycznie wg WCAG).

</details>

<details>
<summary>Semantyczne kolory stanów</summary>

- `primary` / `primaryLight` / `primaryDark`
- `success` / `successLight`
- `warning` / `warningLight`
- `error` / `errorLight`
- `info` / `infoLight`

Każdy wariant `*Light` jest wstępnie zabarwiony na potrzeby badge'y,

</details>

<summary>System</summary>

- `divider` - Separatory list.
- `shadow` - Kolor elewacji (cień w iOS, elevation w Androidzie).

## 4. Własny akcent (nadpisanie marki)

Jeden kolor hex. Gotowe.

</Translated>

```tsx
<NativeUIProvider config={{ customAccent: '#7C3AED', colorMode: 'system' }}>
```

<Translated lang="en">

Internally `customAccent` flows through `tintColor()` and the contrast
picker so:

- `primary` = your hex
- `primaryLight` = your hex at ~15 % alpha (for tinted surfaces)
- `primaryDark` = your hex luminance-shifted for pressed states
- `textOnPrimary` = auto-picked black/white for WCAG AA on your hex

> **Trade-off.** `customAccent` overrides **only** the primary family.
> `success` / `error` / neutrals stay on the preset. If you need
> full brand-level overrides, use the `semantic` prop instead (next
> section).

---

## 5. Semantic token overrides

For a complete rebrand, pass a partial `semantic` object. Anything you
omit falls back to the preset defaults, so you only override what you
care about.

</Translated>

<Translated lang="pl">

Wewnętrznie `customAccent` przechodzi przez `tintColor()` i mechanizm
doboru kontrastu, więc:

- `primary` = Twój hex
- `primaryLight` = Twój hex z ~15 % alfa (dla zabarwionych powierzchni)
- `primaryDark` = Twój hex z przesuniętą luminancją dla stanów wciśnięcia
- `textOnPrimary` = automatycznie dobrany czarny/biały, spełniający WCAG AA na Twoim kolorze

> **Kompromis.** `customAccent` nadpisuje **tylko** rodzinę primary.
> `success` / `error` / kolory neutralne pozostają z presetu. Jeśli
> potrzebujesz pełnych nadpisań na poziomie marki, użyj zamiast tego
> propa `semantic` (następna sekcja).

## 5. Nadpisywanie tokenów semantycznych

Przy pełnej zmianie identyfikacji przekaż częściowy obiekt `semantic`.
Wszystko, co pominiesz, wraca do domyślnych wartości presetu, więc
nadpisujesz tylko to, na czym Ci zależy.

</Translated>

```tsx
<NativeUIProvider
  config={{
    preset: 'default',
    semantic: {
      colors: {
        brand: '#0066CC',
        brandMuted: '#DCE8F4',
        danger: '#D32F2F',
      },
      spacing: { screenGutter: 20 }, // default is 16
    },
  }}
>
```

<Translated lang="en">

Components that consume semantic aliases (`useSemantic()`) switch
instantly. Good candidates for per-app override: `brand`, `danger`,
`successToneBg`, `screenGutter`.

## 6. Accessibility toggles

All four toggles compose; every component responds without any prop
drilling.

| Config | Effect |
|---|---|
| `fontSize: 'large'` | +4 px across every type variant, matching iOS "Larger Text". |
| `highContrast: true` | Promotes `textSecondary` to `textPrimary` weight / opacity. |
| `reduceAnimations: true` | `PressableScale` and `Skeleton` skip animations; `BottomSheet` / `Toast` use instant transitions. |
| `fontColor: 'warm'` / `'cool'` | Tints text tokens by ±2° on the color wheel for eye strain. |

</Translated>

<Translated lang="pl">

Komponenty korzystające z aliasów semantycznych (`useSemantic()`)
przełączają się natychmiast. Dobrzy kandydaci do nadpisania per aplikacja:
`brand`, `danger`, `successToneBg`, `screenGutter`.

---

## 6. Przełączniki dostępności

Wszystkie cztery przełączniki można łączyć; każdy komponent reaguje bez
przekazywania propsów w dół drzewa.

| Konfiguracja | Efekt |
|---|---|
| `fontSize: 'large'` | +4 px w każdym wariancie typografii, zgodnie z „Larger Text” w iOS. |
| `highContrast: true` | Podnosi `textSecondary` do wagi / krycia `textPrimary`. |
| `reduceAnimations: true` | `PressableScale` i `Skeleton` pomijają animacje; `BottomSheet` / `Toast` używają natychmiastowych przejść. |
| `fontColor: 'warm'` / `'cool'` | Zabarwia tokeny tekstu o ±2° na kole barw, aby zmniejszyć zmęczenie oczu. |

</Translated>

```tsx
<NativeUIProvider
  config={{
    fontSize: 'large',
    highContrast: true,
    reduceAnimations: true,
  }}
>
```

<Translated lang="en">

> **Pair with OS preferences.** In real apps, drive these values from
> `AccessibilityInfo.isReduceMotionEnabled()` and
> `PixelRatio.getFontScale()` rather than hard-coding them.

## 8. Korzystanie z motywu we własnych komponentach

</Translated>

```tsx
import { useTheme, useColors, useSemantic } from '@polprog/native-ui';

// Heaviest: full theme object (re-renders on any token change)
const theme = useTheme();
theme.colors.primary;
theme.typography.h1;
theme.spacing.lg;
theme.borderRadius.md;
theme.elevation.md;

// Medium: just the color scheme
const colors = useColors();

// Lightest: designer-facing aliases (brand, danger, screenGutter, ...)
const semantic = useSemantic();
```

<Translated lang="en">

Pick the smallest hook. They are backed by separate React Contexts so
your custom component only re-renders when the slice it reads actually
changes.

## 9. Przepis na motyw marki

</Translated>

```tsx
const BRAND_CONFIG: NativeUIConfig = {
  colorMode: 'system',
  preset: 'default',
  customAccent: '#00E67A',    // brand accent
  fontColor: 'default',
  fontSize: 'default',
  highContrast: false,
  reduceAnimations: false,
  typography: 'regular',
  semantic: {
    colors: {
      brand: '#00E67A',
      brandMuted: '#DCFCE7',
    },
  },
};

export default function App() {
  return (
    <NativeUIProvider config={BRAND_CONFIG}>
      <Root />
    </NativeUIProvider>
  );
}
```

<Translated lang="en">

> **Do not** spread theme config through app state if you can avoid it.
> Pin it to a module constant - React will skip the reconciliation cost
> of a new config object on every render.
