# Example app

Expo app (SDK 58, React Native 0.88) that renders `@polprog/native-ui` on a
real iOS or Android runtime. Storybook shows the components through
`react-native-web`; this app is where native behavior is checked: touch
targets, the keyboard, sheets, safe areas, screen readers.

It consumes the library the way an app does: through the npm workspace link
and the package `exports` map. Metro picks the `react-native` condition, so
the app runs the TypeScript sources. `src/sections/ThemeProbe.tsx` imports
`useTheme` from the `/theme` subpath while the provider comes from the root
entry, which only works when both resolve to one copy of the library.

## Run it

```bash
npm ci                                    # from the repository root
npm run ios --workspace=@polprog/example  # or: npm run android --workspace=@polprog/example
```

The `ios/` and `android/` folders are generated by `expo prebuild` and are not
committed. The scripts call it with
`--skip-dependency-update expo,react,react-native`, so prebuild keeps the
versions this workspace pins instead of rewriting them to Expo's defaults: the
app has to run the same React and React Native as the library's tests.

Expo requires `expo`, `react` and `react-native` under `dependencies`, so the
dependency audit in CI (`audit-ci`, runtime dependencies) covers this app's
toolchain too. The root `package.json` overrides `minimatch` for
`@expo/fingerprint` with a patched release (GHSA-g3hv-75wg-m249); drop the
override once Expo depends on a fixed version itself.

On macOS, CocoaPods needs a UTF-8 locale (`export LANG=en_US.UTF-8`).

## Checks

```bash
npm run typecheck --workspace=@polprog/example
npm run lint --workspace=@polprog/example
```

## Maestro flow

`.maestro/gallery.yaml` walks the screen once: banner, tabs, accordion,
stepper, code entry and the action sheet.

```bash
npm run e2e --workspace=@polprog/example   # needs Maestro and a running build
```

The flow is not part of CI yet and has not been executed by Maestro: it was
written against the test IDs in `src/`, and its steps were walked through by
hand on an iOS simulator (iPhone 16, iOS 18.4) and on an Android emulator
(Android 15). Run it once locally before wiring it into a workflow.

## Release builds and library changes

A release build bundles the JavaScript into the app. Gradle only watches this
folder, so after a change in `packages/native-ui` it reports the bundle task
as up to date and ships the old code. Rebuild the bundle explicitly:

```bash
cd android && ./gradlew :app:createBundleReleaseJsAndAssets --rerun-tasks && ./gradlew assembleRelease
```

Xcode runs its bundle phase on every build, and `npm run ios` /
`npm run android` (debug builds served by Metro) always load the current
sources.
